## 0. 一句话模型

整个函数就三件事：

```
打分  →  归一化  →  加权平均
```

- **打分**：每个 token 拿自己的 `Q`，去和所有 token 的 `K` 比一遍，得到一串分数
- **归一化**：把分数变成加起来等于 1 的权重
- **加权平均**：按权重把所有人的 `V` 混起来，作为自己的新表示

你的代码就是这三件事，中间插了三个补丁：缩放、mask、dropout。

## 1. 形状表（先看这个，再看代码）

设 `B=1, N=3, d_k=4`。

| 步骤 | 变量 | 形状 | 每个数字的含义 |
|---|---|---|---|
| 输入 | `Q` / `K` / `V` | `(1, 3, 4)` | 3 个 token，每个用 4 个数字表示 |
| ① `Q @ K^T` | `scores` | `(1, 3, 3)` | `[b, i, j]` = 第 i 个 token 给第 j 个 token 打的分 |
| ② `÷√d_k` | `scores` | `(1, 3, 3)` | 形状不变，数值缩小 |
| ③ `softmax(-1)` | `attn` | `(1, 3, 3)` | `[b, i, j]` = 第 i 个 token 分给第 j 个的注意力比例，**每行和 = 1** |
| ④ `attn @ V` | `out` | `(1, 3, 4)` | 又回到 `(B, N, d_k)`，可以喂给下一层 |

**唯一变的是中间那个 `(B, N, N)`**。输入输出形状一样，中间冒出一个 N×N 的方阵。这个方阵就是 attention 的全部内容。

为什么是 N×N？因为「每个 token 都要看每个 token」，N 个看 N 个，就是 N² 个组合。这也是 attention 计算量随序列长度**平方增长**的原因——N 翻倍，这个矩阵大 4 倍。

## 2. 用真实数字走一遍

固定随机种子，`B=1, N=3, d_k=4`。

**输入**（每个 token 用 4 个数字表示）：

```
Q =
   +0.803  +0.175  +0.089  -0.614        <- token 0 的提问
   +0.046  -1.368  +0.337  +1.011        <- token 1 的提问
   -1.435  +0.977  +0.522  +1.238        <- token 2 的提问

K =
   -0.865  +0.299  +0.419  -0.080        <- token 0 的标签
   +0.926  +0.816  +0.495  -0.164        <- token 1 的标签
   -0.678  -1.059  +0.748  +0.239        <- token 2 的标签
```

**① 打分 `scores = Q @ K^T`，形状 `(1, 3, 3)`**

```
   -0.556  +1.032  -0.810
   -0.388  -1.072  +1.912
   +1.653  -0.477  +0.624
```

读第一行：token 0 给 token 0 打 −0.556，给 token 1 打 +1.032，给 token 2 打 −0.810。
分数越高说明「token 0 的提问」和「那个 token 的标签」越合拍。

**② 缩放，除以 `√4 = 2`**

```
   -0.278  +0.516  -0.405
   -0.194  -0.536  +0.956
   +0.827  -0.239  +0.312
```

**③ `softmax(dim=-1)`，形状 `(1, 3, 3)`**

```
   +0.244  +0.540  +0.215          每行求和 = 1.0
   +0.205  +0.146  +0.649          每行求和 = 1.0
   +0.515  +0.177  +0.308          每行求和 = 1.0
```

读第一行：token 0 把 24.4% 的注意力给了自己，54.0% 给了 token 1，21.5% 给了 token 2。

**④ `out = attn @ V`，形状 `(1, 3, 4)`**

```
   -0.782  -0.300  +0.083  +0.311
   +0.002  -0.053  +0.650  +1.022
   -0.320  -0.030  -0.169  +0.681
```

**手算校验第一行**，证明这一步就是加权平均：

```
0.244 × v0 + 0.540 × v1 + 0.215 × v2 = [-0.782418, -0.30042, 0.083039, 0.311184]
程序算出的 out[0, 0]                  = [-0.782418, -0.30042, 0.083039, 0.311184]
```

完全一致。**`out` 的每一行，就是 `V` 按权重搅出来的一杯混合果汁。** 权重不同，混合比例不同。

## 3. 逐行讲你的代码

### `d_k = Q.size(-1)`

`Q` 是 `(B, N, d_k)`，`size(-1)` 取最后一个维度，就是 `d_k`。

为什么用 `size(-1)` 而不是写死 64？因为这个函数不知道外面用的是多大的 `d_k`，得从输入现读。这也是为什么函数能同时服务 `d_k=64` 的 ViT 和 `d_k=4` 的玩具例子。

### `scores = torch.matmul(Q, K.transpose(-2, -1))`

这是全篇最关键的一行，分两半看。

**先看 `K.transpose(-2, -1)`**：把 `K` 的最后两维交换。

```
(B, N, d_k)  --transpose(-2,-1)-->  (B, d_k, N)
(1, 3, 4)    ------------------>   (1, 4, 3)
```

**再看 `matmul`**：

```
(B, N, d_k) @ (B, d_k, N)
   (1, 3, 4) @ (1, 4, 3)  ->  (1, 3, 3)
```

矩阵乘法的规则是「前面的列数 = 后面的行数」，两边都是 `d_k=4`，所以能乘。乘完 `d_k` 被消掉，剩下两个 `N`，就是那个 N×N 方阵。

**为什么必须转置？** 不转置就是 `(1,3,4) @ (1,3,4)`，列数 4 和行数 3 对不上，直接报错。转置不只是为了凑形状——它把「比对」这件事表达出来了：`Q` 的每一行去乘 `K` 的每一行，得到的就是两个 token 的相似度。

> 用 `-2, -1` 而不是 `1, 2` 的原因：万一以后加了 head 维变成 `(B, h, N, d_k)`，`-2, -1` 依然正确，写 `1, 2` 就错了。你的写法已经为 D4 的多头做好了准备。

### `scores = scores / math.sqrt(d_k)`

分数是 `d_k` 项相乘再相加得到的。项数越多，加出来的数越容易偏大。

偏大会坏事：`softmax` 会把大数放大成 1、小的压成 0，权重退化成「只看一个」，而且梯度几乎传不回去，训练不动。除以 `√d_k` 把分数拉回正常范围。

**为什么是 `√d_k` 不是 `d_k`？** 因为算出来的分数，波动幅度大约就是 `√d_k` 这个量级（方差是 `d_k`，标准差是 `√d_k`），要除就除标准差。

具体的实测数字（不缩放会退化成 `100% / 0% / 0%`）在 `attention_math.md` 第 3 节。

### `if mask is not None: scores = scores.masked_fill(mask, float('-inf'))`

`masked_fill(mask, value)` 的作用是：**`mask` 里为 `True` 的位置，把值换成 `value`。**

你的 `mask` 语义是「`True` = 屏蔽掉」。这个约定必须记牢，因为反过来写不会报错，只会算错——实测反着写会直接出 `NaN`。

填 `-inf` 的原因：`softmax` 里 `exp(-inf) = 0`，所以被屏蔽的位置权重严格为 0，等于「看不见它」。

**为什么必须在 `softmax` 之前？** 因为 `softmax` 要保证每行和为 1。如果在 `softmax` 之后再把某些位置清零，行和就不再是 1 了。实测（`N=3`，causal）：

```
加在 softmax 之前（你的做法）：行和 = [1.0, 1.0, 1.0]
加在 softmax 之后（错误做法）：行和 = [0.099, 0.519, 0.577, ...]   <- 不再是 1
```

行和不是 1，就意味着「注意力总量」不守恒，后面的加权平均失去意义。

**causal mask 长什么样**（`N=3`，`True` = 屏蔽）：

```
token 0:  保留   屏蔽   屏蔽        权重 [1.000, 0.000, 0.000]
token 1:  保留   保留   屏蔽   ->   权重 [0.585, 0.415, 0.000]
token 2:  保留   保留   保留        权重 [0.515, 0.177, 0.308]
```

看第一行：token 0 只能看自己，所以权重是 `1.000`。这就是「因果」的含义——第 i 个位置只能看到 j ≤ i，不能偷看未来。

### `attn = F.softmax(scores, dim=-1)`

`dim=-1` 作用在最后一维，也就是那 N 个 key 上，让**每一行**加起来等于 1。

为什么是最后一维？因为权重的定义是「第 i 个 query 把多少比例的注意力分给第 j 个 key」。固定 i（即固定一行），在所有 j 上分配完，所以要在 j 这一维上归一化——而 j 正是最后一维。

**这是最容易写错且最难发现的地方。** 如果写成 `dim=-2`，程序照样跑完、loss 照样下降，但归一化方向变成了「每列和为 1」，和定义正好正交。它不会报错，因为形状完全合法。防御手段是一行断言：

```python
assert torch.allclose(attn.sum(-1), torch.ones_like(attn.sum(-1)), atol=1e-6)
```

### `if dropout > 0.0: attn = F.dropout(attn, p=dropout, training=trainning)`

dropout 加在**「softmax 之后、`@ V` 之前」**，也就是作用在权重矩阵上。这是论文里的标准位置，实测和官方实现完全一致（同一个种子下 `p=0.3` 最大差 `0.000e+00`）。

作用是什么：训练时随机把一部分权重置零，逼模型不要依赖某几个固定的 token。

`training=trainning` 这个参数决定了 eval 时要不要丢。`F.dropout` 在 `training=False` 时**直接直通、不做任何处理**，所以推理阶段权重不会被破坏。实测 `training=False` 时输出与完全不传 dropout 完全一致。

### `out = torch.matmul(attn, V)`

```
(B, N, N) @ (B, N, d_k)  ->  (B, N, d_k)
  (1, 3, 3) @ (1, 3, 4)  ->  (1, 3, 4)
```

`attn` 的每一行是一组权重，`V` 的每一行是一个 token 的内容。矩阵乘法在这里的含义就是「按权重求和」，所以结果回到了 `(B, N, d_k)`，形状和输入一样，可以继续往下一层传。

## 4. 三处建议改的地方

### 4.1 参数名拼写：`trainning` → `training`

`trainning` 多了一个 `n`。现在不影响运行，因为默认值是 `True`，不传就没事。但只要有人（包括三个月后的你自己）按 PyTorch 的习惯写 `training=False`，就会直接报错：

```
TypeError: scaled_dot_product_attention() got an unexpected keyword argument 'training'
```

D3 之后要接 `nn.Module`，那时候会用 `self.training`，这个名字必须是对的。

### 4.2 `float('-inf')` 在「整行被屏蔽」时会出 `NaN`

`-inf` 本身没问题，causal mask 下也不会出问题（第 0 行总保留了自己）。但如果某个位置**整行都被屏蔽**，`softmax` 会算出 `-inf - (-inf) = NaN`，然后 NaN 会沿着后面的计算一路扩散。

实测：

```
他的写法 float('-inf')   -> 输出含 NaN: True
改用 finfo.min           -> 输出含 NaN: False
官方 SDPA 同样输入        -> 输出含 NaN: False
```

什么时候会整行被屏蔽？**padding mask**。一批句子里长短不一，短的用 pad 补齐，如果某个位置本身是 pad 且要求它不看任何东西，就会出现整行屏蔽。T1 用的是固定尺寸图片，暂时碰不到；但这是个真实的坑，D3 补 padding mask 时会遇到。

改法：

```python
scores = scores.masked_fill(mask, torch.finfo(scores.dtype).min)
```

用当前 dtype 能表示的最小有限数，避免 `-inf` 参与运算。顺便注意 `float('-inf')` 在 float16 下也容易出问题，`finfo` 会自动跟着 dtype 走。

### 4.3 docstring 过时 + 步骤编号重复

两处小问题：

- docstring 里写 `mask: D2 暂不处理, 留到 D3 加 causal / padding mask`，但你实际上已经实现了 mask。这行该更新了，不然三个月后你会以为它没实现。
- docstring 里写的参数名是 `dropout_p`，实际参数名是 `dropout`。
- 注释编号有两个 `3.`（「施加 mask」和「归一化」），改成 `3.` 和 `4.`。
